# Цифровая Тюмень · LEGAL PRO

Пять независимых интерактивных прототипов. Все дела, решения и сценарии записи учебные. Никакие обращения не отправляются, персональные данные и документы не собираются.

## Маршруты

| URL | Сценарий |
| --- | --- |
| `/prototypes/` | Каталог пяти концепций |
| `/prototypes/central-court/` | Центральный районный суд г. Тюмени: поиск дела, карточка, движение, заседания, список подготовки |
| `/prototypes/magistrate-2/` | Участок № 2 Центрального судебного района г. Тюмени: дела, расписание, навигатор обращения |
| `/prototypes/administration/` | Поиск городской задачи, тематическая структура, маршрут обращения |
| `/prototypes/duma/` | Учебные решения по темам, понятная карточка, учебная запись на прием |
| `/prototypes/vdpo/` | Подбор услуги, тип объекта, чек-лист, учебный маршрут обучения |

## Разработка

React 19, Vite 6, Lucide React. `npm ci`, затем `npm run dev`. Сборка: `npm run build`. Проверка защищенного серверного шаблона Sites: `npm run test:sites`.

`qa.html` — локальный стенд проверки в iframe шириной 360, 390, 768 и 1200 пикселей. Он не включается в production-сборку.

Сборка оставляет все готовые публичные файлы в `dist/client/prototypes/`, с настоящим `index.html` для каждого маршрута. Каталог самодостаточен и не требует API, серверного рендеринга или переписывания всех адресов на корневую страницу. Родительская `dist/client/index.html` нужна только отдельному предпросмотру Sites; **ее нельзя подменять главной prolg.ru**.

## Размещение на prolg.ru

Действующий сайт работает на сервере REG.RU. GitHub `main` — старая заглушка; он не является снимком текущего серверного релиза. Фактический механизм публикации читает `production/deploy.json` репозитория `777LegalPro/legal-pro-maintenance`.

Для первого добавления раздела:

1. Прочитать свежий `production/deploy.json` и подтвердить последний успешный релиз на сервере командой состояния установленного runner. Не считать Git HEAD доказательством применения.
2. Сохранить оба поля текущего HTML заглушки и `maintenance:true`.
3. Передать только новые `prototypes/**` через `files[]`. `expected_sha256:null` предназначен для первого добавления и не перезаписывает отличающиеся файлы. Для последующих обновлений нужны хеши существующих файлов.
4. Скрипт `scripts/make-prolg-manifest.mjs` собирает кандидат из свежего базового манифеста и готового каталога. Он ничего не публикует. Сначала идут ресурсы с хешами, затем HTML. Не более 50 файлов и 4 MiB данных.
5. Отдельно проверить действующий nginx. Если режим технических работ стоит в `location /`, потребуется выделенный обработчик `/prototypes/`, при сохранении заглушки для `/`. Конкретный конфиг надо сверить на сервере; исходник bootstrap не доказывает его актуальное состояние.
6. После применения проверить главную, каталог, все пять прямых адресов и загрузку ресурсов.

Все остальные разделы, главная, настройки домена, авторизация и инфраструктура не входят в эту поставку.
